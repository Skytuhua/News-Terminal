# Local AI compatibility, 18 October 2026

## Intent and design

Allow a reader with an existing LM Studio or llama.cpp server to request optional
summaries through the server's OpenAI-compatible API. Reading remains independent
of AI availability. Do not install a runtime, download a model, invoke live
inference during development, add cloud inference, or change source permissions.

Add one optional provider, `openai-local`, with an explicitly configured model
and `baseUrl`. Accept only HTTP loopback endpoints with an explicit non-default
port and the `/v1` base path. Normalize `localhost` to `127.0.0.1` before a
connection. Disable proxies and redirects, bound requests and responses, and
retain the existing request timeout, cancellation and consent gates. Send only
plain text to `/v1/chat/completions`; reject incomplete or tool responses.

The provider appears disabled in Settings until the reader explicitly saves it.
Existing Ollama settings and the installed-model connection action remain
available. An Ollama attempt first checks the selected entry in `/api/tags` and
rejects known remote model metadata before sending excerpts. A loopback URL is a
transport restriction, not proof that a server executes locally. Settings and
the setup guide state that Ollama cloud features, LM Link, and other remote
delegation must be disabled in the selected runtime.

Persist only the new provider's canonical `baseUrl`, model and existing public
settings. Local providers do not load or save API credentials. Backups accept an
optional `openai-local` record alongside the three legacy provider records;
old backups remain accepted. Import keeps the existing reset of provider
enablement and consent. No new IPC operation or native integration seam is
required.

## Implementation and verification plan

1. Add shared local-provider configuration validation and the compatible request
   and response path; add the Ollama metadata check before content is sent.
2. Extend provider save and backup validation without importing secrets or
   changing legacy defaults. Keep all source and item rights checks in place.
3. Add the optional endpoint/model form and align summary readiness with the
   host's local-only inference policy. Explain local routing limitations.
4. Add focused service tests for endpoint restrictions, consent, request bounds,
   response validation, remote metadata and cancellation; add database tests for
   save/backup/import, plus a Settings/summary browser regression.
5. Run available focused checks, record the exact results and remaining limits,
   then submit the isolated change for independent review.

## Author review and validation

The implemented change keeps the provider optional until an explicit save. No
database migration, new IPC operation, dependency or lockfile change is needed.
The host advances its provider generation on saves, and the sector fingerprint
includes complete provider records with `baseUrl`. Those guards cancel or
reject work when settings change. The existing import transaction
resets every provider's enablement and consent. Both local adapters reject
explicit cloud-tagged model identifiers; the Ollama adapter also checks the
selected model's metadata before sending source content.

Added eleven service tests covering configuration, request scope and budgets,
strict completion parsing, remote metadata, real fixture HTTP, cancellation and
permission gates. Added four database tests for optional configuration,
canonicalization, secret exclusion, legacy backups and atomic rejection.
Added three browser fixture cases for Settings consent, article readiness and
sector quotation generation. The existing ignored Ollama HTTP fixture now
answers the required metadata request before its completion response.

The initial implementation was frozen in a partial Linux source mirror, then
applied unchanged to a full project worktree at baseline
`8834fbc20240917abdd7dce3846eb2c541b7d975`. The exact transfer patch passed
`git apply --check`. No product or fixture fixes were needed during the full
project frontend checks below. No live inference or runtime installation was
performed.

A second agent completed a read-only source review of the full patch. Its two
fixture findings were corrected: database unit tests belong below a nested
test directory, and the shared browser fixture explicitly records an undefined
top-level `apiKey` field. No further actionable findings remained in that
review. This review does not replace native compilation and test execution.
