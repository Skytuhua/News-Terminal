# Browser and native harness support

Goal: run the existing verification from an explicit checkout, with independent
ports and artifacts, and preserve failures without leaving an owned Vite server.

The browser wrappers and Playwright config currently hardcode port 1420. The
wrapper also resolves its CLI and Vite root from the caller's working directory.
This breaks an absolute script invocation from another folder and prevents
independent harness runs in separate worktrees.

## Plan

- Reproduce invocation from a temporary folder with spaces, invalid port input,
  and an occupied selected port using real child processes.
- Share validated loopback port, artifact paths and optional browser executable
  settings between the wrappers and Playwright config.
- Resolve the checkout from the script location, pass child arguments without a
  shell, and close the owned server on success, test failure and launch failure.
- Add discoverable npm aliases for listing tests and the existing native daily
  and feature suites. Document Windows requirements and fixture/native limits.
- Verify the process controls, TypeScript, and an existing browser journey on a
  nondefault port. Independent review precedes merging.

Files: package.json, .gitignore, playwright.config.ts, scripts/run-playwright.mjs,
scripts/playwright-vite-server.mjs, a shared harness configuration helper and its
declaration, tests/harness-launch.test.ts, and docs/development.md.

No dependency, source permission, user data, or production fixture changes.

## Validation

- The initial process suite reproduced three failures: an absolute invocation
  from a folder with spaces used the wrong CLI path, a malformed port was ignored,
  and a selected occupied port was ignored. All three controls pass after the fix.
- Five process checks pass, including output-directory protection and preserving
  a real discovery failure while leaving its selected port reusable.
- The complete unit suite passes: 55 tests. TypeScript and git diff checks pass.
- A cold-cache browser run on port 1434 passes both existing reader journeys in
  8.7 seconds, including the normal no-native-runtime screen and fixture
  select/save/search/open behavior. Default HTML reporting also completes.
- An earlier cold run exposed Babel processing the generated React bundle when
  the isolated cache lived outside a node_modules path. The cache now remains
  per checkout and port beneath .cache/node_modules, matching the React plugin's
  dependency exclusion. The cold run above used a new cache and unchanged test
  timeouts; the earlier failure is not counted as a pass.

Native npm aliases invoke existing real-host runners. Native acceptance still
requires a fresh Windows executable and separate execution; these browser and
process results do not establish installer or WebView2 acceptance.

## Independent review fixes

Review against `c8700d4` found that the image zoom journey created a separate
browser context on port 1420. It now inherits the selected project's base URL,
so a run on another port cannot enter a different checkout's fixture server.

The output-directory guard checked lexical containment only. A temporary proof
showed that a child path beneath a symbolic link or Windows junction could reach
outside `test-results`, where Playwright's recursive cleanup would remove files.
The guard now rejects links and junctions along the selected path before running
Playwright. A real-process regression failed before the guard change and passed
afterward. Its marker and directories are synthetic fixtures created by the test.

The discovery-failure control now starts Vite before it exercises the failure;
`--list` had bypassed server startup. All six focused process checks pass after
these fixes, and TypeScript and diff checks pass. These review checks ran on
Linux with loopback access. The image zoom journey also passes on port 1434
with Chrome for Testing 155, including its separate 200% zoom context.
Windows signal cleanup was inspected but was not exercised by these local checks.
